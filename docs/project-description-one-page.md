# MoonReconcile 项目说明

**项目：** MoonReconcile——基于 MoonBit 的表格对账与差异解释工具<br>
**仓库：** <https://github.com/z2823253773-p/moonreconcile><br>
**用途：** 对两份 CSV 导出建立可追溯的记录对应、字段差异说明与人工复核报告。

## 问题与方案

来自两个系统或不同时间点的表格，可能有列名变化、编号异常、状态编码不一致、数值或日期差异和单边记录。简单逐行比较容易把行顺序变化当成内容变化；只看相似度又不能证明两条记录代表同一对象。MoonReconcile 把流程分成导入、列映射与显式规则、记录对应、字段比较、人工复核和报告导出六个阶段。引擎先用左右均唯一、有效的显式键自动对应；其他对应仅生成有竞争信息的建议，必须由人接受。报告保留规则、输入快照和决定依据。

核心算法、CSV 语义、规则校验、精确十进制与日期比较、候选评分、部分分配、决定重放及报告数据均由 MoonBit 实现。Node.js 负责命令行、文件读写、哈希和安全发布输出。CLI 四命令为 `init-config`、`check-config`、`compare`、`resolve`。首版只读写 CSV，不包含 XLSX、数据库、多人协作或自动学习匹配规则。

## 场景与现有工具

仓库提供订单核对、系统迁移验收、商品目录对应三个完整合成流程，另有真实公开CSV版本维护案例：OurAirports两期CN/FR数据共2558/2569条记录，以官方稳定ID对应，独立逐值对照确认11新增、18字段变化；公开CLI跑通核对、处置与累计重放，来源和哈希可复现。现有工具文档显示 MoonRow 覆盖组合键 CSV 比较，DataComPy 提供容差和结构化比较，Python Record Linkage Toolkit 提供候选生成与字段比较。本项目尝试在一个 MoonBit 核心和 CLI 中连起显式映射、业务规则、剩余候选、决定回导和追溯报告；目前只有文档层面对照，没有在本机实测竞品，也没有证明真实需求或生态缺口。

## 已有验证

本地门禁包括 MoonBit 核心测试、Node 桥接与 CLI 测试、240 个独立小图分配穷举对照、三个合成工作流和独立库消费。留存的合成基准在 Darwin 25.4.0 arm64、Node 24.15.0 与 Moon 0.1.20260713 环境中测得：精确核对每侧 1,000 / 10,000 行分别为 125.839 / 342.846 ms；稀疏候选每侧 10,000 / 30,000 行的中位数为 297.867 / 726.061 ms。密集分量和候选对预算超限均返回退出码 3 并标记未完成。峰值 RSS 因主机权限限制不可得。上述基准数据为合成数据，数字是观察值，不是容量或性能保证。公开数据案例另见 [OurAirports复现说明](../examples/ourairports/README.md)。
