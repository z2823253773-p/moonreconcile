# 本机工作台使用与范围

运行包内置 Node.js 主机代码、编译后的 MoonBit bridge 和锁定的生产 npm 依赖。启动与处理不执行 `npm install`、不调用 `moon` 或 Python，也不访问远端服务；程序要求 Node.js 22 或更高版本，使用页面还需要一款已安装的本机浏览器，运行包不会下载浏览器。工作台不代替原始文件备份，请保留自己的输入副本。

## 文件与会话

运行 `node workbench/start.mjs` 后，程序只绑定回环地址 `127.0.0.1`，终端会显示本机 URL 和随机会话令牌。令牌用于保护本机 API；不要分享含令牌的地址。工作台不自动打开浏览器。浏览器关闭不会自动停止后台进程，应回到启动终端按 `Ctrl+C`。

每次启动会在系统临时目录创建独立、仅当前用户可读写的会话目录。正常退出会关闭子进程并清理仅属于该会话的目录。强制结束或系统崩溃可能留下临时目录；先确认没有对应运行进程，再检查目录内 `.owner` 标记，确认后手动处理。程序不会扫描或清理其他临时目录。已下载的运行 ZIP 不在会话目录中，需由使用者自行保存和管理。

页面连续 30 分钟没有操作时，会提示导出配置或运行 ZIP。提示不会删除会话或修改规则；继续输入、点击、滚动等操作即可收起提示并重新计时。浏览器休眠或后台限时可能延后提示，后台服务仍需在启动终端停止。

## 支持的流程

- 导入两侧严格 UTF-8 CSV，并完整校验后分页查看预览和单元格。
- 受限 XLSX 导入代码支持显式选择可见工作表、矩形范围和每列转换方式；公式拒绝，隐藏行与筛选范围警告保留所有选中数据行。当前激活候选默认提供 CSV / XLSX 选择；Task 7 仍等待干净激活 SHA 的完整门禁、同一保留 ZIP 的离线／浏览器／CLI 证据及最终独立全分支审查。
- 从当前列创建空白 Config v1 草稿，或载入 JSON 配置；使用表单编辑左右来源列映射、文本/十进制/日期类型、主键、参与逐字段比较选项、容差、左右值映射和候选评分字段/指标/权重/阈值，再由 MoonBit 核心校验。
- 运行比较，查看汇总、配对、字段差异、候选、原值和来源格；人工提交接受、否决、左侧独有或右侧独有决定。
- 导入累计决定 CSV。已应用决定属于对应结果版本；需要从干净比较重新开始时，从原始结果建立分支。分支与累计回导会重新运行核心，旧版本保留用于查看。
- 导出 JSON、Markdown 和 CSV 证据，保存完整运行 ZIP；恢复时验证包内路径、文件清单、CRC、SHA-256、结构与大小限制，再重放 CLI 并要求报告逐字节一致。

建议分数不是概率，候选需要人工判断。状态 `different` 只描述声明规则下的字段不等，不自动说明业务原因或实际影响。Config v1 是逐表映射和显式比较规则表单，不支持通用 Excel 编辑、拆分或合并工作表、公式、跨表关系或业务审批流程。

## 受限 XLSX 的选择与追溯（激活候选待最终验收）

必须明确选择一张可见的普通工作表、包含表头的矩形范围，并为范围内每一列指定模式。程序不猜首张表、列类型、键或日期系统，不计算公式。以下是已实现适配器的四种列模式；当前激活候选默认入口提供 CSV / XLSX。

| 模式 | 转换行为 |
| --- | --- |
| `stored_text` | 文本保留解码后的存储内容，布尔值转成 `TRUE`/`FALSE`，数值保留工作簿内的数值词元；不模拟 Excel 显示格式。 |
| `decimal_lexeme` | 只接受数值单元格，把十进制或科学计数词元展开成精确十进制文本，不经过浮点舍入。 |
| `excel_date` | 只接受无时间部分的非负整数日期序列，按工作簿已验证的 1900/1904 日期系统转成日期；拒绝 1900 序列 60。 |
| `zero_padded_identifier` | 只接受非负整数数值和纯 `0` 数字格式，按该格式宽度补前导零；不猜测其他数字格式。 |

选择范围内的空白数据行、隐藏行和筛选范围内的行都保留，不按可见状态删除；相应范围/隐藏/筛选警告随导入材料保存。来源格查看区分工作簿实际存储值 `stored_value` 与转换后进入规范 CSV 的 `imported_value`，并给出工作表、坐标、列模式、样式及数字格式。已经被 Excel 保存时舍入的精度无法恢复。

原始 XLSX、规范 CSV、转换 profile 和 adapter manifest 分别有独立 SHA-256；原件身份、转换规则与转换结果不能互相替代。行映射把核心逻辑记录对应回工作表物理行，转换警告和材料清单保留在适配器层；MoonBit 核心 manifest 仍是 v1。

纯 CSV 运行 ZIP 保留原来的 12 文件结构；一侧 XLSX 加一侧 CSV 的 v2 包有 16 项材料，两侧 XLSX 的 v2 包有 19 项。恢复先校验全部路径、大小、CRC、清单及哈希，再用保留的原件和 profile 完整重新转换，要求规范 CSV 字节与哈希一致，并重放原核心、要求报告逐字节相同；全部通过后才原子发布恢复结果。任何失败都保留原有会话结果。

## 规则中的特殊字符串

逻辑字段名、值映射的键和值、缺失标记、候选字段和引用列表使用转义文本。普通文字直接输入；换行写 `\n`，回车写 `\r`，CRLF 写 `\r\n`，制表符写 `\t`，双引号写 `\"`，一个反斜杠写 `\\`，其他控制字符可写 `\uXXXX`。这些表示方式与 JSON 字符串内部相同，无需在表单里添加外层引号或编辑整份 JSON。例如，`item\ncode` 表示带换行的名称，`item\\ncode` 表示包含字面反斜杠和字母 n 的名称。来源列下拉框显示同样的转义文字，选择后仍使用完整原始表头。

主键、忽略列和每个 Blocking 分组一行一项，空白行不计入列表：空白输入表示 `[]`，一行 `\e` 表示 `[""]`，一行 `\\e` 表示包含字面 `\e` 的一项。缺失标记使用逐项控件；添加后留空表示一个空字符串，删除该行才会移除这一项。引用是否有效仍由核心校验，例如空字符串引用不会自动变成空列表。

未完成或非法的转义会保留在对应控件，并暂时禁用“校验并保存规则”；修正后才能保存。翻页和表单重绘不会丢掉这段输入，删除某项则同时删除该项的未完成输入。校验成功后的导出配置恢复为实际字符串，重新导入仍以核心规范配置为准。

## 资源上限

当前运行守卫如下；这些值是拒绝超限输入的保护边界，不代表达到上限时的吞吐或内存承诺。

| 项目 | 上限 |
| --- | ---: |
| 单个 CSV、配置或一般资产 | 64 MiB |
| 单个 CSV 数据逻辑行 | 100,000 |
| CSV 列数 | 256 |
| 单元格 UTF-8 字节 | 64 KiB |
| 会话目录总量 | 1 GiB |
| 会话资产 / 导入 / 结果版本 | 64 / 64 / 32 |
| 上传请求并发 / 核心子进程 | 1 / 1 |
| 核心任务时间 / 上传时间 | 180 秒 / 60 秒 |
| ZIP 压缩大小 / 解压大小 / 文件条目 | 256 MiB / 1 GiB / 32 |
| HTTP JSON 请求 / 展示响应 | 1 MiB / 2 MiB |

决策 CSV 的核心规则另行允许最多 128 MiB 原始模板和 400,000 数据行；有效非空动作最多 100,000 行，规范 CSV 最多 64 MiB。具体的错误与退出码以 CLI 和核心返回为准。

## CLI 与结果状态

包内独立命令行入口为 `node cli/main.mjs --help`。可用命令包括 `init-config`、`check-config`、`compare` 和 `resolve`。命令行和工作台使用同一 `runtime/bridge.js`，复核报告使用相同的 MoonBit 核心语义。

退出码 `0` 表示完成且无差异或待复核项，`1` 表示完整结果仍有差异或复核项，`2` 表示输入、配置或 I/O 错误，`3` 表示计算未完成。状态和差异须分开解释；有报告文件不代表计算完整或所有业务差异已经解决。
