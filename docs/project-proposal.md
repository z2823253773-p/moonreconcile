## 1. 要解决的问题

两个系统导出的表格，即使描述同一批对象，也可能存在列名不一致、编号异常、状态编码不同、金额或日期表示不同、部分记录缺失等情况。仅输出“文件有差异”，不能说明哪些行实际对应；仅给出相似度，也不能证明两行就是同一对象，更不能替代核对内容和保存复核决定。

MoonReconcile 拟提供一个可复用的 MoonBit 核心与命令行入口，将**导入、列映射与规则、记录对应、字段解释、人工复核和最终导出**连接起来。用户应能看到每项结论来自原始值、哪条规则或哪次人工决定，并带走仍未解决的问题。

当前需求依据是设计推演，尚未取得可复现的真实使用流程、实际人工耗时或误配成本。这个缺口必须保留在项目评价中，不能用三个合成演示代替。

## 2. 三个目标业务流程

| 流程 | 典型输入与处理 | 复核之后的交付 | 首版边界 |
| --- | --- | --- | --- |
| 两套订单系统核对 | 每单一行；映射不同列名，以可靠唯一订单键对应，再比较状态、金额、日期和单边记录 | 对应表、字段差异、人工确认的无对应记录、待调查清单 | 不处理拆单、合单或多笔付款对一张订单 |
| 系统迁移前后验收 | 迁移前后导出表；检查改名、遗漏、未映射列、明确允许的转换及异常键 | 可接受转换与实际差异的区分、结构问题、复核记录 | 规则必须显式声明；程序不替业务负责人决定是否验收 |
| 两家供应商目录建立对应 | 两侧 ID 不同；按品牌、名称、规格等生成候选，展示竞争关系并给出一对一建议 | 人工接受的商品对应表、拒绝理由、明确无对应与待处理记录 | 名称相似不证明身份；所有候选建议需人工接受 |

三个演示均计划使用**明确标注的合成数据**。每个演示必须跑完“输入 → compare → 编辑决定 → resolve → 最终报告”，不能只展示一段评分结果。

## 3. 首版完整功能

1. **导入与检查。** 读取 UTF-8 CSV，检查标题、重复列、行宽、逻辑记录编号、必需列和资源预算；保留原值。含换行字段按一条逻辑记录编号。
2. **映射与规则。** 左右来源列映射到逻辑字段，身份字段与内容字段可分开；显式设置组合键、忽略列、ASCII 空白/大小写处理、单次有限值映射和缺失标记。未映射且未忽略的列必须报告。
3. **可靠对应与候选。** 有效、非缺失、非空且左右各唯一的规范化键才能自动对应。其余记录保持待处理，可按配置生成候选；分组规则可选，超预算明确停止或标记受影响部分。
4. **字段差异解释。** 文本保留前导零；十进制采用精确运算；日期严格接受有效 `YYYY-MM-DD`。展示原值、处理后值、规则、差值、容差和结果；解释观察到的变化，不猜测财务或业务根因。
5. **人工复核回导。** 支持接受、拒绝、确认左侧无对应、确认右侧无对应。候选外人工对应需要理由；互相矛盾的决定整批拒绝；接受记录对应后继续展示内容差异。
6. **追溯与最终导出。** 保存输入快照、规范化配置、版本与指纹；输出 JSON、对应 CSV、字段 CSV、候选/决定 CSV、未解决清单和 Markdown 汇总。删除原路径文件后，仍应能使用运行快照复核。

拟议命令如下；实际可运行状态以 README 和验收记录为准：

```sh
reconcile init-config left.csv right.csv --out rules.json
reconcile check-config rules.json
reconcile compare left.csv right.csv --config rules.json --out run-001
reconcile resolve run-001 --decisions reviewed.csv --out run-001-reviewed
```

`init-config` 生成待填写模板，不猜类型或主键。`check-config` 检查内部一致性；真实输入列和键唯一性在 `compare` 中检查。

## 4. MoonBit 技术路线

### 核心与宿主边界

| 部分 | 负责内容 | 不应承担的内容 |
| --- | --- | --- |
| MoonBit 核心 | 严格 CSV 语义、配置校验、转换和类型规则、精确键、候选评分、最大权部分匹配、决定校验、结果状态与报告数据 | 原文件路径管理、终端参数、平台文件事务 |
| Node.js 适配层 | UTF-8 字节解码、文件读取、SHA-256、磁盘检查、输出目录事务、参数解析和报告序列化 | 业务匹配、十进制比较、配对决策或重新计算核心统计 |

优先使用 MoonBit JavaScript target，通过纯 JSON 请求/响应接口连接宿主。核心库与 CLI 分离，以便后续更换文件入口；更换入口不应重写业务规则。CSV 依赖需要依据实际输入契约评估；文档或宽松解析器存在，不等于满足严格报错要求。

### 数值与匹配方法

十进制按符号、数字和标度进行精确计算，输入至多 64 位数字、小数至多 18 位，中间运算不截断。规则为：

```text
abs(left - right) <= max(abs_tol, rel_tol * max(abs(left), abs(right)))
```

日期比较采用严格日历解析和绝对天数容差。解析失败是 `invalid_value`，不得退回字符串比较。双方缺失能否算内容相等由规则决定；身份评分中空值或缺失不能构成匹配证据。

候选支持精确文本、Unicode 码点编辑相似度、十进制和日期容差评分。总分采用固定分母的整数加权平均；缺失字段不从分母移除，分数不是概率。对阈值合格图的连通分量使用带虚拟未匹配节点的 Hungarian 最大权部分匹配，并展示竞争候选。首版只有唯一键对应自动成立，所有算法建议都需人工确认。

### 状态与可追溯性

每侧记录必须满足：

```text
paired + unmatched + pending_review + unprocessed = 输入记录数
```

`paired` 来源只能是 `exact_key` 或 `human_review`；`unmatched` 表示人工确认无对应。算法计算完整和人工复核完成分开报告。一次运行曾因资源预算未完成候选计算，即使后来人工处理完所有记录，也保留该计算历史及退出码 3。

退出码定义为：0 为计算完整且无须处理的问题；1 为计算完整但存在差异或未决项；2 为输入、配置、决定或 I/O 错误；3 为资源导致计算不完整。优先级为 `2 > 3 > 1 > 0`。

## 5. 现有工具重叠与预期区别

截至 2026-09-30 的[原始文档对照](dependency-audit.md#6-相邻工具能力对照文档核查未在本仓库运行)显示：MoonRow 已覆盖 MoonBit 组合键 CSV 快照比较和报告；DataComPy 已提供可配置容差、自定义比较器与结构化报告；Python Record Linkage Toolkit 已提供候选对和多种字段比较。拟议差异是把显式映射、业务规则、剩余候选、人工决定回导和追溯报告串成 MoonBit 主导的工作流。这些能力仍须由本项目实际交付并与现有办法对照，不能因设计稿写出组合就宣称需求已验证。

拟验证的区别是：**在同一个 MoonBit 核心和 CLI 中，完成显式列映射、业务规则、剩余候选、人工决定回导和可追溯最终报告。** 精确关联、一个相似度算法、多种输出格式都不能单独充当创新依据。

对照分两层：先用“精确关联 + 业务规则”比较有共同键的完整核对，再在带人工真值的样例中记录候选找到的正确对应、错误建议和复核负担。合成真值仅用于检验算法和演示，不外推为真实准确率或节省工时。若现有工具已能便捷完成真实流程且本项目无可观察收益，应暂停独立产品投入，考虑贡献现有生态。

## 6. 实施与验收

| 阶段 | 可审查成果 | 必要验收 |
| --- | --- | --- |
| 1. 运行时、导入、配置 | MoonBit/Node 桥、严格 CSV、配置合同 | 畸形输入拒绝、原值与逻辑行号保留、模板不猜键或类型 |
| 2. 规则引擎 | 十进制、日期、文本、缺失与转换 | 精确容差边界、闰年、前导零、无效值、映射不递归 |
| 3. 精确对应 | 键诊断、结构报告、字段结果 | 重复/缺失/空键不误配、列顺序不影响映射、计数守恒 |
| 4. 候选与分配 | 分组、评分、竞争候选、一对一建议 | 小图独立穷举对照、贪心失败样例、阈值和预算边界 |
| 5. 人工复核 | 决定校验、累计重放、人工覆盖 | 冲突原子拒绝、理由和来源保留、幂等、差异继续呈现 |
| 6. 文件闭环 | CLI、快照、指纹、最终报告 | 原文件不改写、指纹不一致拒绝、写入失败不伪装成功 |
| 7. 场景与规模 | 三组完整合成流程、可复现实测 | 1000/10000 行精确核对和不同候选密度；记录环境、时间、内存可得性及输出大小 |
| 8. 交付 | 文档、许可证、CI、公开代码与策划书 | 干净检出复跑、精确提交 SHA、远端 CI 和仓库可见性证据 |

## 7. 资源边界与风险

| 环节 | 初始保护预算 | 预期失败语义 |
| --- | --- | --- |
| 输入 | 每文件 64 MiB、100000 条逻辑记录、256 列、每格 64 KiB UTF-8 | 输入报错，不截断继续 |
| 候选生成 | 最多 100000 个去重候选对 | 停止剩余候选阶段，保留已完成精确对应并标记不完整 |
| 分配求解 | 阈值合格分量每侧至多 100 条记录 | 该分量未处理，其他可处理分量继续 |
| 编辑距离 | 每字段 512 码点、累计 20000000 个动态规划单元 | 明示受影响范围，不能删除昂贵边后宣称完整 |

最大产品风险是缺少真实流程和可观察收益。最优先的后续需求证据包括：有权处理的输入来源、文件规模、现有步骤、业务规则、误配代价及当前耗时或错误基线。敏感原始数据不进入公开仓库。

CSV 是首个入口，但真实流程是否可无损导出仍未验证。若仅有 XLSX，或导出会丢失前导零、日期等必要信息，则只读工作表适配成为该场景的交付前提，需要重新估算；当前不承诺公式重算。

首版不处理拆合单、自动学习权重、猜列或主键、远程数据库、多人协作、源表改写、任意时区和公式重算。指纹用于识别过期或不一致材料，不提供抗恶意篡改认证。公共代码交付、测试通过、真实用户验收、赛事重审通过和获奖是不同事实。

赛事时间及资格以当前官方要求和组委会回复为准。本项目策划及实现不能保证审核结果；后续宣传只能描述有对应证据的已交付能力。
