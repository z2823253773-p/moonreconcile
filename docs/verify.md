# Local verification

Run `make verify` from a clean Git checkout to rebuild and exercise the locally accepted A+C workbench at one exact source commit. The command checks tracked bytes against `HEAD`, downloads or reuses pinned Node 22.23.3 and Moon archives only after validating hardcoded SHA-256 values, runs the MoonBit, Node, workbench, browser, package, consumer, oracle, workflow, public-data, and README gates, builds a fresh package in a unique system-temporary directory, then runs the strict relocated-package validator against that package. It fails at the first nonzero stage or timeout.

The Node and Moon archives live under the ignored project-local `.verify/` cache. Each invocation checks the archive digests and compares installed immutable files and links against the verified archives; it also rebuilds Moon core bundles from the verified core sources. npm's cache, Playwright's pinned Chromium, temporary files, logs, and summaries stay in `.verify/`. No global PATH, shell files, SDK directories, or browser installation is changed.

The supported bootstrap locks are macOS arm64 and Linux x86_64. The Moon archive URL uses the vendor's mutable `latest` selector, but a changed archive fails the pinned digest check until a reviewed lock update is made. The Node archive is versioned at 22.23.3 and its digest is also fixed in source. Bootstrap failure is recorded as failure; a version string or marker file alone never validates a cache.

Prerequisites are Python 3, Git, Make, network access for an uncached bootstrap and npm/Chromium downloads, and a clean source tree. Linux also needs the system libraries required by Chromium plus `sudo`, `unshare`, and `ip`; strict validation opens a real network namespace and brings up loopback. macOS strict validation requires `/usr/bin/sandbox-exec`; the checker runs outside that sandbox so it can perform its external-network positive control before it tests the isolated child. If those prerequisites are unavailable, the gate fails with that boundary instead of counting as passed.

Every stage has a separate log. The run's `summary.json` records source SHA, platform, actual tool versions and archive digests, each exit code, duration, timeout, package locations, and final source identity. The run directory is `.verify/runs/<UTC-time>-<pid>/`. A passing local run is evidence for that local source SHA only; it does not establish remote CI, Linux execution from a macOS run, user adoption, competition eligibility, or submission.

`make verify-unit` runs only the verifier's safety regressions. `python3 scripts/verify.py --bootstrap-only` removes its dedicated extracted toolchains and rechecks/reuses only pinned archives under `.verify/bootstrap-probe/downloads/`, then tests extraction and setup without running product gates. Neither command is a full acceptance result.
